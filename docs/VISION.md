# HOPNIC Platform Vision

- **Recorded:** 2026-07-09, from owner (CHiP) direction
- **Framing (agreed):** เป้าหมายระยะยาวเหล่านี้เป็น "ทิศ" ไม่ใช่ "งานปัจจุบัน" — **design วันนี้แค่อย่าปิดประตู** ไปถึงภาพนี้ ยังไม่ commit สร้างสิ่งเหล่านี้ และห้ามใช้ vision เป็นเหตุ over-engineer งานเฉพาะหน้า
- **Purpose:** ให้ทุก session/agent เห็นปลายทางเดียวกันเวลาตัดสินใจเชิงโครงสร้าง (schema, provenance, branch dimension ฯลฯ)

---

## วิสัยทัศน์ 8 ข้อ

1. **Multi-branch, DB เดียว** — Database นี้ต่อไปจะถูกใช้โดยทุกสาขา (โครงสร้างข้อมูลเงิน/สต็อก/booking ต้องเดินไปทางผูก branch ได้ ไม่ล็อกตายกับสาขาเดียว)
2. **เอกสาร digital ถูกกฎหมายไทยทุกขั้นตอน** — ทุกขั้นตอนของธุรกรรมต้องออกเอกสาร digital ที่ใช้ตามกฎหมายจริงในประเทศไทยได้ (ใบเสร็จ ใบกำกับภาษี ฯลฯ)
3. **การจัดการที่ดีครบทุกมิติ:**
   - 3.1 Content
   - 3.2 User — ลูกค้าทั่วไป, พนักงาน, Admin Web; ในอนาคตอาจมี B2B และ Partner
   - 3.3 Branch
   - 3.4 Stock
   - 3.5 Account
   - 3.6 ERP
4. **ลดคนในสาขา** — ระบบต้องตอบโจทย์การใช้พนักงานหน้าร้านน้อยลง
5. **มีข้อมูลหลังบ้านให้วิเคราะห์** — analytics บนข้อมูลที่เก็บอย่างเป็นระบบ
6. **เป็น Community** — เชื่อมคน งาน และธุรกิจ (ระยะหลัง)
7. **Search & Matching ด้วย AI** — เช่นการ post หางาน: อนาคตจะใช้ **DeepSeek AI ที่เรา custom** กรองความต้องการ → วิเคราะห์ตาม Categories ที่เรามี → Matching ร้านค้า คน และบริการให้ได้ (partner taxonomy ใน DB คือฐานของข้อนี้ — `partner_category_assignments` มี `source`/`confidence` เผื่อ `ai_extracted` ไว้แล้ว)
8. **AI ช่วยงาน Admin จัดข้อมูลเข้า DB** — การอัปสินค้าใน Web Admin ให้กรอกข้อมูลดิบได้จาก Catalog หรือแหล่งใดก็ตาม แล้วใช้ DeepSeek AI custom กรอง/จัดโครงสร้างข้อมูลเข้า Database ให้ (pattern: AI เสนอ → คน approve → เข้า DB)

## Focus ปัจจุบัน (first-branch launch)

1. **สาขาแรกต้องปล่อยเช่าได้:**
   - 1.1 ลูกค้าตามสถานะของได้
   - 1.2 POS: พนักงานออกเอกสารให้ลูกค้าได้
   - 1.3 POS: ขายของที่มี stock หน้าร้านได้
   - 1.4 POS: เก็บข้อมูล KYC ลูกค้า walk-in ได้
   - 1.5 การจอง/เช่า พนักงานกดแทนได้เพียงลูกค้าแจ้งเบอร์ — แต่ต้องบันทึกคนที่ทำ (actor logging)
2. **เอกสารมาตรฐานหน้าตาเดียวกัน** — เป็น HTML ที่ทำเพื่อ print เป็น PDF ได้ ยอมรับได้ ไม่ติดใจ engine

## Decision ที่ผูกกับ vision นี้

- **POS V3 เท่านั้น** (2026-07-09): v1 จะถูกปลดระวาง — V3 ต้อง feature-complete (sale + fiscal docs + KYC + return/settlement) ก่อน launch, ออกแบบเพื่อ **iPad เครื่องเดียว**, พนักงานที่ไม่ใช่สายเทคนิคต้องเข้าใจง่าย

- ข้อ 7–8 (AI): วันนี้รักษาไว้แค่สองอย่าง — taxonomy สะอาด และข้อมูลมี provenance (ใครใส่ อะไร เมื่อไหร่) — ห้าม design abstraction เผื่อ AI เกินจำเป็น
